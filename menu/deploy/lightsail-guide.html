Launch a 90-day private AI pilot on AWS Lightsail.

A practical small-business path for testing private AI without committing to complex infrastructure first.

The simple promise

NoCloudGPT is designed to make private AI feel approachable. The business owner should not need to understand GPU provisioning, model registries, API keys, Docker networking, or reverse proxies before seeing value. With a small AWS Lightsail server, Ollama, OpenWebUI, and a guided NoCloudGPT installation path, a company can test private AI quickly and learn what model size they actually need.

What the customer needs before starting

A small-business owner needs four ordinary items to create the AWS account and launch the pilot:

  • A valid email address for the AWS login.
  • A valid phone number for AWS identity verification.
  • A valid physical address for billing and account records.
  • A valid credit or debit card for the AWS account.

AWS may offer eligible Lightsail bundles with a 90-day free trial. This should be presented as a pilot opportunity, not a permanent guarantee. The customer should always review current AWS terms before launching.

Recommended pilot size

For NoCloudGPT, the pilot should be framed as an AI power level instead of raw infrastructure. Start with Starter AI for the smallest experiments, or Standard AI when the customer wants a more comfortable OpenWebUI experience and room for small Ollama models.

Step 1: Create the AWS account

Go to AWS, create an account, and complete the normal verification flow. The customer enters their email, phone, address, and card. After account verification, they can open the Lightsail service from the AWS console.

Step 2: Create a Lightsail instance

Inside Lightsail, choose a Linux instance. Ubuntu is the default recommendation for most customers because it is familiar, well documented, and compatible with common Ollama and OpenWebUI workflows. Choose a region close to the business. Name the instance clearly, such as nocloudgpt-pilot.

Step 3: Connect to the terminal

After the instance is running, open the built-in Lightsail browser SSH terminal. This keeps the setup simple because the customer does not need to install a local SSH client or manage keys on day one.

Step 4: Run the NoCloudGPT installer

The goal is a one-command setup experience. The customer opens the terminal, pastes the command, and lets the installer do the work.

curl -fsSL https://get.nocloudgpt.com | bash

The installer path should explain what happens in plain English: install system requirements, install Ollama, prepare OpenWebUI, recommend a small model, and print the access URL when complete.

What they get

The customer gets a private AI chat environment they control. NoCloudGPT should position OpenWebUI as the friendly chat interface and Ollama as the local model engine. The customer can start with small models, then upgrade compute or switch models later.

Call to action

Use the 90-day pilot to validate whether private AI helps the business. If it does, NoCloudGPT can transition the customer into a paid platform tier, a larger compute level, or an on-premise deployment.
