FireFunction: Purpose-Built Function Calling AI That Runs On Your Infrastructure, Not Fireworks' Servers

Function calling is the backbone of modern agentic AI — it's how models interact with APIs, databases, and external tools in structured, predictable ways. Most teams rely on OpenAI's function calling API to do this, which means every tool invocation, every parameter payload, and every returned result passes through a third-party server.

FireFunction, developed by Fireworks AI, brings GPT-4-class function calling performance to an open-weight model you can run entirely on your own hardware. Deployed via ollama run firefunction-v2, it gives agentic pipelines the structured output reliability they need — without sending a single tool call off-premise.

---

What FireFunction Actually Does

FireFunction is not a general-purpose chat model with function calling bolted on. It was fine-tuned specifically to produce reliable, schema-conformant structured outputs for tool use and agentic workflows.

  • Structured function calling — generates well-formed JSON tool invocations that conform to defined schemas, reducing parsing failures in production pipelines
  • Multi-tool selection — correctly identifies which tool to call from a provided set, including declining to call when no tool is appropriate
  • Parallel function calls — can invoke multiple tools in a single pass where task decomposition requires it
  • OpenAI-compatible API format — function schemas follow the same structure as OpenAI's tool calling spec, minimizing migration effort for existing pipelines
  • Instruction-following backbone — built on a strong base model capable of reasoning through multi-step task execution before committing to a tool call
  • Low hallucination rate on tool selection — fine-tuned to avoid fabricating tool names or parameters not present in the provided schema

Deployment Tiers and Compute Requirements

Tier 1 — Developer and Pipeline Testing: FireFunction 7B Q4

  • RAM required: 4–6GB
  • Hardware: Developer laptop, AWS Lightsail 8GB, or any modern workstation
  • AWS cost: Lightsail 8GB ~$40/month
  • Speed: 10–20 tokens/sec on CPU
  • Best for: Individual developers building and testing agentic pipelines, schema validation, and function call logic

Run it: ollama run firefunction-v2

Tier 2 — Production Pipeline: FireFunction 7B Q4 on GPU

  • VRAM required: 8GB
  • Hardware: AWS g4dn.xlarge (T4 16GB), RTX 3070/4060 Ti, or equivalent
  • AWS cost: ~$0.526/hour on-demand; ~$0.16/hour spot
  • Speed: 40–70 tokens/sec
  • Best for: Production agentic pipelines with 5–15 concurrent requests, low-latency tool invocation requirements, automated workflow orchestration

Run it: ollama run firefunction-v2

The Real Cost of Function Calling Through External APIs

Every function call routed through OpenAI or a similar provider sends structured data — tool names, parameter schemas, returned values — to external infrastructure. In agentic pipelines, this happens dozens to hundreds of times per workflow execution.

  • Tool call parameters frequently contain internal system identifiers, user data, or business-sensitive values that were never intended to leave your network
  • OpenAI API costs for function-heavy agentic workflows scale rapidly — a pipeline making 50 tool calls per session at GPT-4 pricing can cost $0.50–$2.00 per workflow run
  • At 500 workflow executions per day: $250–$1,000/day in API costs, with no cap and no data control
  • FireFunction on a g4dn.xlarge spot instance handles the same volume for approximately $1.28–$3.84/day

For agentic pipelines, the function call is the payload. Running FireFunction locally means that payload never leaves your environment.
