Run Pixtral 12B Locally with Ollama

Mistral's multimodal vision model — analyze images, documents, and charts without sending visual data to the cloud.

12B Parameters 128K Context Vision + Text Multi-Image Variable Resolution Apache 2.0

Most enterprise AI use cases eventually hit a wall: the data that matters most — contracts with signatures, financial charts, engineering schematics, medical imaging reports, ID documents — exists as images or PDFs, not clean text. Cloud vision APIs can process these files, but doing so means transmitting sensitive visual content to external servers. Pixtral 12B, run locally with Ollama, eliminates that exposure entirely.

Released by Mistral AI in September 2024, Pixtral 12B is the first truly capable open-source multimodal model at this parameter count. It combines a 400M-parameter vision encoder with Mistral Nemo's 12B language backbone, supports variable image resolutions up to high-definition, and can process multiple images in a single context window. For organizations handling confidential visual content, the ability to run Pixtral on local hardware is not a nice-to-have — it is a compliance requirement.

Why Vision Privacy Matters More Than Text Privacy

When professionals think about AI data privacy, they typically focus on the text they type into chat interfaces. But visual data carries far greater risk of sensitive information exposure. Consider what passes through a typical enterprise vision workflow:

A law firm processing discovery materials uploads scanned exhibits — witness signatures, handwritten annotations, physical document metadata — to a cloud vision API. A hospital's radiology department runs AI-assisted report drafting on DICOM-exported images. A financial analyst feeds earnings presentation slides into a vision model to extract chart data before public release. An HR team processes uploaded ID documents for onboarding verification.

In each case, the visual content carries identification, privilege, or confidentiality implications that text summaries alone cannot capture. Cloud vision APIs are technically processing this content on external infrastructure, regardless of contractual protections. Pixtral 12B deployed locally processes every image on your hardware, with no network transmission of visual content.

🔒 What "Local Vision Processing" Actually Means

When you send an image to GPT-4o Vision or Gemini Pro Vision, the image bytes travel across the internet to OpenAI or Google's inference servers. The image is decoded, processed by the model, and the response is transmitted back. Even with data processing agreements in place, the image existed outside your infrastructure. With Pixtral running via Ollama, the image is read from your local filesystem or memory, processed entirely on your GPU, and the response is generated locally. The image never leaves your machine.

One of Pixtral's highest-value enterprise applications is processing scanned documents — contracts, invoices, forms, and reports that exist only as images. Unlike OCR-only solutions, Pixtral understands document structure, layout, and context, enabling extraction that goes beyond raw text.

import ollama, base64

def extract_contract_clauses(scanned_pdf_images: list) -> str:
    """Process multi-page scanned contract."""
    encoded_pages = []
    for path in scanned_pdf_images:
        with open(path, "rb") as f:
            encoded_pages.append(base64.b64encode(f.read()).decode("utf-8"))

    response = ollama.chat(
        model="pixtral",
        messages=[
            {
                "role": "user",
                "content": """Review these contract pages and extract:
                1. Parties involved (names, roles)
                2. Effective date and term
                3. Key obligations of each party
                4. Payment terms and amounts
                5. Termination conditions
                6. Governing law and jurisdiction
                7. Any unusual or non-standard clauses
                
                Flag any clauses that appear to be handwritten additions 
                or differ from standard formatting.""",
                "images": encoded_pages
            }
        ]
    )

    return response['message']['content']

Batch Document Processing

import ollama, base64, json
from pathlib import Path
from concurrent.futures import ThreadPoolExecutor
import time

def process_single_document(doc_path: Path) -> dict:
    """Process one document image through Pixtral locally."""
    with open(doc_path, "rb") as f:
        image_data = base64.b64encode(f.read()).decode("utf-8")

    response = ollama.chat(
        model="pixtral",
        messages=[{
            "role": "user",
            "content": "Classify this document type, extract key metadata, "
                       "and summarize main content in 2-3 sentences.",
            "images": [image_data]
        }]
    )

    return {
        "file": doc_path.name,
        "analysis": response['message']['content'],
        "processed_at": time.time()
    }

def batch_process_documents(folder: str, workers: int = 2) -> list:
    """
    Process folder of document images in parallel.
    workers=2 is conservative for single GPU — increase for multi-GPU setups.
    """
    doc_paths = list(Path(folder).glob("*.{jpg,jpeg,png,webp}"))
    results = []

    with ThreadPoolExecutor(max_workers=workers) as executor:
        futures = {executor.submit(process_single_document, p): p 
                   for p in doc_paths}
        for future in futures:
            try:
                results.append(future.result(timeout=120))
            except Exception as e:
                results.append({"file": str(futures[future]), "error": str(e)})

    return results

# Process entire folder of scanned documents — nothing leaves your server
results = batch_process_documents("/data/incoming_contracts/")
with open("processing_results.json", "w") as f:
    json.dump(results, f, indent=2)

Frequently Asked Questions

What image resolution does Pixtral support?

Pixtral uses a variable-resolution architecture that processes images as patches, supporting resolutions up to 1024×1024 per patch. For most document scanning use cases (300 DPI scans of letter-size pages), Pixtral handles the resolution effectively. Very high-resolution technical drawings may need downsampling to fit within VRAM constraints. Standard document scans at 150–300 DPI work well without modification.

Can Pixtral read handwriting?

Yes, with limitations. Pixtral performs reasonably well on clear, consistent handwriting — printed block letters, neat cursive — but struggles with highly stylized or ambiguous handwriting. For critical handwritten content extraction, validate Pixtral's output against the original. In production workflows, flag all handwriting-derived extractions for human review rather than treating them as ground truth.

How does Pixtral handle PDF documents?

Ollama processes images, not PDFs directly. For PDF workflows, convert each page to an image first using a library like pdf2image (Python) or pdftoppm (CLI). Then pass the page images to Pixtral. This conversion happens entirely locally, maintaining your privacy posture. For multi-page PDFs, you can pass multiple page images in a single Pixtral request up to the context window limit.

Is Pixtral suitable for medical imaging (X-rays, MRIs)?

Pixtral is a general-purpose vision model, not a medical imaging specialist. It can describe and extract text from radiology reports, clinical photos, and administrative medical documents effectively. For diagnostic interpretation of DICOM images (X-rays, MRIs, CT scans), purpose-built medical AI models with clinical validation are more appropriate. Pixtral's strongest healthcare use case is administrative document processing, not diagnostic imaging.
