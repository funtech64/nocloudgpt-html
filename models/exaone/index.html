Exaone: LG's Enterprise-Grade Bilingual AI Model, Running Entirely On Your Infrastructure

Most open-weight models treat language support as an afterthought — English first, everything else approximate. Exaone, developed by LG AI Research, was built differently. It is a bilingual English-Korean model trained with enterprise deployment in mind from the start, covering both code generation and general instruction-following with native fluency in both languages.

For organizations operating across English and Korean-speaking teams — or serving Korean-market customers — Exaone offers something no general-purpose model reliably delivers: consistent quality in both languages, running on hardware you control, with no data leaving your network.

Deploy it today with ollama run exaone3.5.

---

What Exaone Actually Does

Exaone is a general-purpose instruction and code model with strong bilingual capability. It is not a narrow specialist — it handles the full range of developer and knowledge-worker tasks in both English and Korean.

  • Native English-Korean bilingual output — not translation-layer bilingual; trained natively on both languages for consistent reasoning quality across both
  • Code generation and debugging — supports Python, JavaScript, Java, C++, and other major languages with context-aware completions
  • Instruction-following for knowledge work — document summarization, report drafting, structured data extraction, and multi-step task execution
  • Long-context handling — supports extended context windows suitable for document-length inputs and multi-turn conversations
  • Enterprise-oriented training — LG AI Research designed Exaone specifically for professional deployment, not consumer chat applications
  • Multiple size variants — 2.4B for edge and CPU deployments; 7.8B for team servers; 32B for high-demand production environments

Deployment Tiers and Compute Requirements

Tier 1 — Edge and Solo Use: Exaone 2.4B Q4

  • RAM required: 2–4GB
  • Hardware: Developer laptop, Mac Mini, or AWS Lightsail 4GB instance
  • AWS cost: Lightsail 4GB ~$20/month
  • Speed: 10–20 tokens/sec on CPU
  • Best for: Individual developers, offline document drafting, bilingual chat tools, lightweight CI assistants

Run it: ollama run exaone3.5:2.4b

Tier 2 — Team Workstation: Exaone 7.8B Q4

  • RAM required: 6–8GB
  • Hardware: Developer workstation, Mac with 8GB unified memory, AWS Lightsail 8GB, or entry GPU
  • AWS cost: Lightsail 8GB ~$40/month; g4dn.xlarge ~$0.526/hour on-demand
  • Speed: 12–25 tokens/sec on CPU; 35–55 tokens/sec on T4 GPU
  • Best for: Small teams of 3–8 users, bilingual document workflows, code review assistance, Korean-language customer support tooling

Run it: ollama run exaone3.5:7.8b

Tier 3 — Production Server: Exaone 32B Q4

  • RAM required: 20–24GB VRAM
  • Hardware: AWS g5.xlarge (A10G 24GB), RTX 4090, or dual-GPU workstation
  • AWS cost: g5.xlarge ~$1.006/hour on-demand; ~$0.30/hour spot
  • Speed: 20–40 tokens/sec on A10G
  • Best for: 10–25 concurrent users, enterprise knowledge management platforms, high-quality bilingual document generation at scale

Run it: ollama run exaone3.5:32b

The Real Cost of Routing Korean-Language Data Through US Cloud AI

When Korean-language documents, contracts, or code are submitted to OpenAI, Anthropic, or Google APIs, they cross borders — legally and physically. That creates compounding risk:

  • Korean personal data regulations (PIPA) impose strict requirements on cross-border data transfers that cloud AI API usage may violate
  • Proprietary Korean-language business documents processed through US infrastructure are subject to US legal jurisdiction and potential disclosure requirements
  • General-purpose models trained primarily on English data produce lower-quality Korean outputs — errors that may go undetected by non-native reviewers
  • At 10 users on GPT-4 API for mixed English-Korean document workflows: $3,000–$6,000/year in API costs, with zero data control. Exaone 7.8B on AWS Lightsail: ~$480/year, fully on-premise

Exaone was built by a Korean enterprise for enterprise use. Running it locally is not just a cost decision — it is a compliance and quality decision.
