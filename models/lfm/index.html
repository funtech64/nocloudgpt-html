LFM / LFM2: Liquid Foundation Models

Novel Architecture Memory Efficient Edge Capable Liquid AI Open Weights

Architecture note: LFM models are not Transformers. They use Liquid Neural Networks — a continuous-time recurrent architecture derived from computational neuroscience. This gives them a fundamentally different memory and compute profile compared to attention-based models.

LFM (Liquid Foundation Models) and their successor LFM2 are produced by Liquid AI, a MIT spinout working on non-Transformer architectures. The key claim: LFM models are more memory-efficient than Transformer models of comparable capability because they use a fixed-size state (like Mamba/SSM models) rather than a growing KV-cache. LFM2 brings this to open weights at 1.2B, 3.8B, and 8B scales — making it a genuinely different option from the mainstream Llama/Mistral/Gemma landscape.

What LFM / LFM2 Is Good At

  • Memory-efficient inference — fixed state size means memory usage doesn't grow with sequence length
  • Long-context processing with low VRAM — handles long inputs without the KV-cache overhead of Transformer models
  • Instruction following — LFM2 8B performs competitively with Llama 3 8B Instruct on standard benchmarks
  • Edge and constrained deployment — useful where memory is the binding constraint rather than compute
  • Streaming applications — the recurrent nature suits real-time streaming inference scenarios

Who Should Care

Business and Professional Use

LFM2 is worth evaluating for teams with a specific constraint: they need to run a capable AI model in an environment with limited memory (not limited compute). Think embedded servers, edge AI devices, high-concurrency deployments where KV-cache scaling is the bottleneck, or specialized inference hardware. If your deployment is memory-bound rather than compute-bound, LFM2's architecture is a genuine advantage.

Personal and Homelab Use

LFM2 8B is interesting for homelab users experimenting with alternative architectures. It runs with noticeably lower peak memory than a Transformer 8B model. For a standard homelab assistant, Llama 3 or Gemma 2 are better-supported by tooling — but LFM2 is worth experimenting with if you're curious about what post-Transformer models feel like in practice.

Deployment Notes

LFM2 requires inference frameworks with non-Transformer architecture support. Ollama added LFM2 support in recent releases. For custom deployments, Liquid AI provides their own inference code: 

ollama run lfm2:8b

# Or via Liquid AI's inference repo (check HuggingFace)
# Note: standard llama.cpp GGUF may not support LFM2 architecture
# Verify current framework support before production deployment
