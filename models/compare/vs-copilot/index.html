Local AI vs Copilot

Microsoft operates two "Copilot" products with very different privacy profiles. Both send your data to Microsoft's cloud. Here is exactly what that means — and how local AI eliminates that exposure entirely.

🔒Privacy Local wins — zero egress
💰Cost Local wins at scale

Two Products, One Name

Microsoft uses "Copilot" for two distinct products. This page covers both.

GitHub Copilot

AI pair programmer integrated into VS Code, JetBrains, Neovim, and other editors. Powered by OpenAI Codex and GPT-4o models hosted on Azure.

  • Sends surrounding code context with every suggestion
  • Telemetry includes file paths, language, keystroke patterns
  • Business plan: 60-day prompt retention by default
  • Individual plan: prompts may be used for model training
  • $10–$19/user/month depending on tier

Microsoft 365 Copilot

AI assistant integrated into Word, Excel, Teams, Outlook, and SharePoint. Powered by GPT-4 via Azure OpenAI Service.

  • Accesses your entire M365 tenant — emails, docs, meetings
  • Processes content through Microsoft Graph on Azure
  • Enterprise tier: data not used for training
  • $30/user/month (requires M365 E3/E5)
  • Operates within Microsoft's EU Data Boundary (opt-in)
Important Distinction

M365 Copilot for enterprise has stronger data commitments than GitHub Copilot Individual. However, both products process your data on Microsoft's Azure infrastructure, which means CLOUD Act exposure, cross-border transfer obligations under GDPR, and third-party disclosure risk for privileged content all apply.

GitHub Copilot: What Gets Sent

GitHub Copilot's telemetry goes well beyond your current file. Understanding the full data surface is critical for IP and compliance teams.

Code Context Transmission — Every Keystroke

GitHub Copilot sends a "prompt" to Azure on every suggestion request. This prompt includes:

  • The current file's content (up to the cursor position)
  • Related files open in adjacent tabs (neighbour files feature)
  • File path and repository name
  • Programming language identifier
  • Editor version and plugin version telemetry

For a developer working on a proprietary algorithm, this means the algorithm's implementation transmits to Microsoft's Azure infrastructure dozens of times per hour.

The Neighbour Files Feature

Copilot's "neighbour files" feature — enabled by default — includes content from other open editor tabs in the context sent to Azure. A developer with a config file containing API keys, a schema file with PII structure, or an internal README with architecture details open in a background tab will transmit that content even if they are editing an unrelated file.

28-Day Business Tier Retention

GitHub Copilot Business retains prompts (including transmitted code) for 28 days for trust and safety purposes. This is documented in GitHub's privacy statement but is not prominently disclosed during onboarding. Enterprise tier reduces this window but does not eliminate it entirely — a 28-day window is still 28 days of proprietary code on Microsoft's servers.

M365 Copilot: The Broader Surface Area

M365 Copilot's deep tenant integration creates a larger data exposure surface than most AI tools.

Microsoft Graph Access

M365 Copilot operates through Microsoft Graph, which means it has access to — and can include in its prompts to GPT-4 — your organisation's emails, calendar entries, Teams messages, SharePoint documents, and OneDrive files. A single Copilot query like "summarise the key issues in this deal" can pull in privileged legal correspondence, financial projections, and HR communications simultaneously and send them as a combined prompt to Azure OpenAI.

EU Data Boundary — What It Does and Doesn't Cover

Microsoft's EU Data Boundary stores EU customer data within the EU for most M365 services. However:

  • It is an opt-in programme, not the default
  • Certain support and diagnostic data still flows outside the EU
  • It does not override CLOUD Act obligations — EU Data Boundary data can still be compelled under US law
  • The boundary applies at rest and in transit, but the AI processing (GPT-4 inference) occurs on Azure infrastructure that may not be fully boundary-constrained depending on load
What M365 Copilot Does Right

M365 Copilot Enterprise does not use customer data to train foundation models. Microsoft's data processing agreement for enterprise customers is among the most mature in the AI industry. For organisations already operating within Microsoft's ecosystem with appropriate DPAs in place, the incremental risk of M365 Copilot is lower than, say, using ChatGPT or Claude without enterprise agreements. The issue is not recklessness — it is structural cloud exposure that no enterprise agreement can fully eliminate.

Sector Risk Analysis

Where Copilot's cloud architecture creates specific compliance and legal exposure.

💻

Software Engineering

Proprietary algorithms, internal APIs, and unreleased features transmit to Azure continuously during GitHub Copilot use.

IP risk: Developer employment agreements typically include IP assignment clauses. Transmitting proprietary code to a third-party service may create ownership ambiguity under some jurisdictions. Client NDAs almost universally prohibit disclosure of their systems to third parties.

Local alternative: Ollama + Codestral or Llama 3.3 70B via Continue.dev VS Code extension.
⚖️

Legal

M365 Copilot processing legal documents through Microsoft Graph creates third-party disclosure of privileged communications.

Privilege risk: When M365 Copilot reads a privileged email or document as context for a query, that content is transmitted to Azure OpenAI. The voluntary disclosure doctrine may apply in some jurisdictions even when the disclosure is to an AI system operated by a third party.

Local alternative: Mistral Large 2 with local document indexing via LlamaIndex.
🏥

Healthcare

M365 Copilot accessing SharePoint or Teams where PHI is stored can inadvertently include patient data in prompts sent to Azure.

HIPAA risk: Microsoft offers a BAA for M365 that covers Copilot in enterprise configurations. However, the BAA requires careful scoping — Copilot must be configured to exclude PHI-containing data sources. Default configurations may not enforce this boundary.

Local alternative: Llama 3.3 70B on-premises with PHI-isolated document stores.
📈

Finance

Financial analysts using M365 Copilot on Excel models or Teams calls containing MNPI transmit material non-public information to Microsoft's infrastructure.

MNPI risk: Microsoft is not a broker-dealer or regulated financial entity. The chain of custody for MNPI processed through M365 Copilot is not clearly established. Compliance teams at regulated firms should treat any Azure-processed financial content as potentially problematic under SEC guidance.

Local alternative: Mistral Large 2 on an isolated finance VLAN with no internet egress.

When to Use Each

The right answer depends on your data sensitivity and existing Microsoft investment.

Use Local AI When

  • Working with proprietary algorithms or unreleased product code
  • Operating under NDA with clients who prohibit third-party disclosure
  • GDPR, HIPAA, ITAR, or financial regulation applies to your data
  • You need fine-tuned models on your specific codebase
  • Team size makes per-seat licensing prohibitive
  • You need offline or air-gapped operation
  • You want zero CLOUD Act exposure

Copilot Remains Useful For

  • Teams deeply invested in the M365 ecosystem
  • Non-sensitive code on public or open-source projects
  • Developers without local GPU hardware
  • M365 document workflows where AI integration is seamless
  • Organisations with mature Microsoft DPAs already in place
  • Teams that need Copilot's polished IDE UX without setup friction
