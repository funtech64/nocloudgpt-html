Reader-LM — Convert Any Web Page to Clean Markdown for Your Private RAG Pipeline

Reader-LM is Jina AI's purpose-built web content extraction model — it takes raw HTML, including the noise of ads, navigation, scripts, and boilerplate, and returns clean markdown containing only the meaningful content. Deploy it privately as the ingestion layer for a RAG system that never sends your target URLs or their content to a cloud service.

Every retrieval-augmented generation system needs an ingestion layer — something that takes content from the world and transforms it into a form suitable for embedding, chunking, and retrieval. For web content, this ingestion problem is surprisingly hard. A typical web page is 70–90% noise: navigation menus, advertisement containers, cookie consent banners, JavaScript bundles, social share widgets, footer links, and tracking pixels. The actual article, documentation, or product content that you want to index is buried in this structure, and simple HTML stripping produces text that is nearly as noisy as the original HTML.

Reader-LM solves this problem with a model specifically trained to distinguish meaningful content from structural and decorative noise. Given raw HTML, it returns clean markdown — headings preserved, code blocks formatted, tables structured, lists maintained, and boilerplate removed. The result feeds directly into the embedding step of a RAG pipeline without requiring the additional preprocessing steps that general-purpose HTML cleaning tools typically need.

Reader-LM 2 is the current version, released by Jina AI in 2024. It is available in 0.5B and 1.5B parameter versions, both small enough to run on CPU-only hardware at practical speeds for batch and real-time ingestion workflows. The model supports documents up to 256K tokens, handling even the longest technical documentation pages and dense research articles. Private deployment means the URLs you are ingesting, the content of those pages, and the structure of your knowledge base never leave your infrastructure.

Why the Ingestion Layer Matters as Much as the LLM

RAG system quality is determined at every stage of the pipeline, and the ingestion and extraction stage is where most production systems underperform. An embedding model working on poorly extracted, noise-contaminated text will produce embeddings that don't reliably cluster by meaning. A retrieval system working on those embeddings will return chunks that contain the right topic surrounded by irrelevant navigational content. And the LLM generating the final answer will either ignore the noise and miss context, or include it and produce confused, poorly-grounded responses.

Reader-LM addresses this at the root. Clean extraction means cleaner chunks, better embeddings, more reliable retrieval, and ultimately more accurate generated answers. For organizations investing in private RAG infrastructure, the extraction layer is often the most neglected component and the one that produces the most improvement when done properly.

The privacy dimension of the ingestion layer is also underappreciated. Organizations building competitive intelligence systems, research monitoring tools, or internal knowledge bases often use non-public or sensitive URLs as sources. Routing these through Jina AI's public reader API — or any external service — means revealing what you are monitoring, researching, or indexing to a third party. Private Reader-LM deployment means your research targets and ingest patterns stay internal.

Where Reader-LM Consistently Delivers

RAG pipeline web ingestion

As the first stage in a retrieval pipeline, Reader-LM converts crawled or fetched HTML into clean markdown that feeds directly into chunking and embedding steps. The structured output — with preserved headings, code blocks, and tables — produces chunks that embed more meaningfully than raw-text extraction.

Technical documentation indexing

API reference pages, developer documentation, and technical wikis are structurally complex HTML — nested navigation, code samples, version selectors, and cross-reference links. Reader-LM extracts the actual content while preserving the code block structure and heading hierarchy that makes technical documentation useful when retrieved.

News and research article extraction

News pages, academic preprint servers, and research publication sites wrap thin content in heavy advertising and tracking infrastructure. Reader-LM reliably identifies and extracts article content, bylines, dates, and structured body text while discarding the surrounding noise.

E-commerce and product page extraction

Product descriptions, specifications, pricing information, and structured attributes from e-commerce pages — extracted cleanly for competitive monitoring, catalog building, and price tracking systems. The consistent markdown output simplifies the downstream parsing and database population steps.

Internal wiki and intranet content indexing

Confluence pages, Notion exports, SharePoint documents, and internal wikis are often HTML-heavy and structurally inconsistent. Reader-LM normalizes this content into clean markdown suitable for a private enterprise search and RAG system — without routing internal documentation through any external service.

Competitive intelligence monitoring

Monitoring competitor websites, press release pages, regulatory filings, and job postings requires ingesting content that reveals what you are tracking. Private Reader-LM deployment means your monitoring targets stay confidential while the extraction quality supports reliable change detection and content analysis.

Who Should Be Running Reader-LM

Organizations building private RAG systems

Any team deploying a private retrieval-augmented generation system that ingests web content should evaluate Reader-LM as the extraction layer. The alternative — using Jina's public API, a cloud-based scraping service, or a general-purpose HTML parser — trades either privacy, cost, or extraction quality. Reader-LM running locally provides better extraction quality than rule-based parsers, better privacy than any cloud service, and no per-page cost once deployed.

Research and intelligence teams

Investment analysts monitoring financial filings and press releases, policy researchers tracking regulatory publications, competitive intelligence teams monitoring industry developments, and academic researchers systematically reviewing publications all benefit from private Reader-LM deployment. The extraction quality enables reliable content analysis, and private deployment means research targets and monitoring patterns stay confidential.

Developer tooling and documentation systems

Development teams building internal documentation search, code assistant tools that can read external documentation, or developer portals that aggregate technical content need a reliable extraction layer for web-sourced material. Reader-LM's handling of code blocks and technical HTML structure makes it particularly well-suited for developer-facing knowledge systems.
