terminal.glass deployment wizard

Where do you want your AI to live?

terminal.glass should give customers an easy path to connect, not ask them to hand over server access. The customer buys Sunrise, receives Glass Licenses, chooses a deployment path, and the deployment activates outward to the terminal.glass license dashboard.

Install on my server

NoCloudGPT

Local/private GPT host running on customer-owned hardware, office Linux servers, homelabs, clinics, shops, churches, or other customer-controlled systems.

  • Ollama-backed local/private model runtime
  • OpenWebUI browser chat interface
  • Best when the customer wants maximum local control

Launch in my cloud

YourCloudGPT

Customer-owned cloud deployment, starting with AWS/Lightsail-style paths. The customer owns the cloud account while terminal.glass provides the install and activation path.

  • Good first paid rollout path
  • Works with Passport activation and private installer delivery
  • Useful when office hardware is not ready

Add action workers

Glass Agents

OpenClaw-based workers that can act inside an approved customer environment. Glass Agents are the action-capable lane for file, server, workflow, and later Alchemist-directed tasks.

  • OpenClaw-powered action agent lane
  • Customer-approved environment boundary
  • Future detachable OpenClaw-Glass beta path

Add cloud-model help

Jet Agents

Curated cloud-model lanes for speed, coding, research, drafting, and model variety. Jet Agents are not separate licenses; they are capabilities available inside the Glass License package.

  • Useful when GPU hardware is too expensive
  • Helps customers compare answers from different models
  • Supports big-model workflows such as Nemotron-style or GPT-OSS cloud lanes

Customer-safe deployment flow

  1. Customer buys Sunrise Starter or Sunrise Group Plan.
  2. Customer receives portable Glass Licenses.
  3. Customer chooses where AI lives: server, cloud, Glass Agent, or Jet Agent lane.
  4. terminal.glass generates an activation or bootstrap path.
  5. The customer runs the install or launch path in their own environment.
  6. The deployment activates outward to the terminal.glass license authority.
  7. The customer chats on their own terminal.glass/NoCloudGPT instance.

Trust message

terminal.glass does not need access to your server by default.

Your deployment activates outward to your terminal.glass license dashboard. Support can still offer white-glove help later, but the standard customer path should preserve customer control.
