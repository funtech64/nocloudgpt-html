The Story Behind the Numbers

When OpenChat 3.5 dropped its benchmark results in November 2023, the local AI community did a double-take. An MT-Bench score of 7.81 put it above Llama 2 70B Chat (6.27), above WizardLM 70B (7.71), and level with GPT-3.5 Turbo (7.94 at the time) — on a 7 billion parameter model trained on a dataset smaller than what most research labs call a "small" fine-tune.

The Tsinghua NLP group's key insight was that conventional RLHF treats all training examples the same: collect human feedback, train a reward model, use PPO to update the policy. Expensive, unstable, and prone to reward hacking. Their alternative — Conditioned Reinforcement Learning from Feedback Training (C-RLFT) — asks a different question: what if you could tell the model, at training time, which examples came from high-quality sources and which didn't?

🔬 How C-RLFT Works (Plain English)

Conventional RLHF trains a reward model to score outputs, then uses PPO to maximize that score. C-RLFT takes a simpler, more elegant path.

1
Collect mixed-quality data

Gather instruction-response pairs from multiple sources — some from GPT-4 (high quality), some from GPT-3.5 (medium), some from weaker models or humans (variable). Label each pair with its source.

2
Condition on quality signal

Instead of a separate reward model, inject a quality token directly into the prompt during training. High-quality examples get a "good" condition token; lower-quality get a different token.

3
Inference: always condition on "best"

At inference time, always use the "high quality" condition token. The model learned which response style is associated with that token and generates accordingly — no reward model, no PPO, no instability.

4
Result: data efficiency

Because you're not training a reward model separately, you need far fewer examples. The quality signal is embedded in the conditioning, not learned from millions of comparison pairs. 6,000 examples suffices where conventional RLHF might need 100,000+.

🔵
Why this matters for local AI

C-RLFT's efficiency means the approach is reproducible at smaller compute scales. Labs and individuals without access to massive GPU clusters can produce competitive fine-tunes. This is part of why the local AI ecosystem has improved so rapidly — the algorithmic techniques to get more from less data are maturing fast.

The 8K Context Tradeoff

OpenChat 3.5's largest practical limitation is its 8,192-token context window. While this is double the original Mistral 7B's default, it falls short of the 32K offered by Nous Hermes 2 and Zephyr, or the 128K in Llama 3.1 8B.

In practice, 8K tokens handles roughly 6,000 words — enough for most chat interactions, short document summaries, and moderate-length code reviews. It becomes limiting when you need to feed in full contracts, entire codebases, or lengthy research papers as context.

OpenChat Prompt Format

OpenChat uses a custom prompt format distinct from ChatML. Ollama handles this automatically, but if you're using the model directly via the GGUF or calling the REST API, you need to format prompts correctly.

OpenChat 3.5 Prompt Format
GPT4 Correct User: {user_message}<|end_of_turn|>GPT4 Correct Assistant:
💡
Why "GPT4 Correct" in the prompt?

The C-RLFT conditioning token in OpenChat is implemented as a special role name in the prompt. GPT4 Correct User signals "high quality" to the model — it was trained to associate this label with GPT-4-sourced, high-quality responses. Using the wrong role name (like a plain User:) degrades output quality measurably. Ollama handles this mapping for you automatically.

Python Integration via Ollama

python openchat_client.py 
from openai import OpenAI

# Ollama exposes an OpenAI-compatible endpoint
client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",  # required but unused
)

def ask(question: str, system: str = "") -> str:
    messages = []
    if system:
        messages.append({"role": "system", "content": system})
    messages.append({"role": "user", "content": question})

    response = client.chat.completions.create(
        model="openchat",
        messages=messages,
        temperature=0.7,
        max_tokens=2048,
    )
    return response.choices[0].message.content

# Example usage
result = ask(
    question="Explain the CAP theorem and its practical implications.",
    system="You are a distributed systems expert. Be precise and technical."
)
print(result)

Streaming Responses

python — streaming stream.py 
import requests, json, sys

def stream_chat(prompt: str) -> None:
    payload = {
        "model": "openchat",
        "messages": [{"role": "user", "content": prompt}],
        "stream": True,
    }
    with requests.post(
        "http://localhost:11434/api/chat",
        json=payload, stream=True
    ) as r:
        for line in r.iter_lines():
            if line:
                chunk = json.loads(line)
                if "message" in chunk:
                    sys.stdout.write(chunk["message"]["content"])
                    sys.stdout.flush()
    print()  # newline after stream ends

stream_chat("Write a brief overview of transformer architecture.")

Best Use Cases

💬

Conversational AI Assistants

OpenChat's strongest benchmark is MT-Bench — multi-turn conversation quality. For chatbot interfaces, customer support drafting, or interactive Q&A, it punches well above its 7B weight.

⚡

Low-Latency Applications

At 7B parameters with INT4 quantization, OpenChat delivers 20–40 tokens/sec on consumer GPUs — fast enough for real-time response streaming in production applications.

🖥️

Moderate Code Assistance

HumanEval at 55% makes it a reasonable coding assistant for standard tasks — function completion, debugging help, explaining code. For complex multi-file projects, see WizardCoder or Llama 3.1 8B.

🎓

Educational Applications

Clean, coherent explanations with good instruction-following make OpenChat an effective tutoring assistant. Its C-RLFT training on GPT-4 outputs means it inherited GPT-4's explanatory style.

🔌

Drop-in GPT-3.5 Replacement

For internal tooling built around the OpenAI API, OpenChat via Ollama's OpenAI-compatible endpoint is the cleanest local replacement. MT-Bench scores suggest you'd barely notice the difference on most everyday tasks.

🧪

Research Baseline

C-RLFT's novel training approach makes OpenChat 3.5 a useful research baseline for studying data-efficient fine-tuning. The training methodology is openly documented in the paper.

When to still choose OpenChat over Llama 3.1 8B

If you need Apache 2.0 licensing (Llama 3.1's Community License has restrictions above 700M monthly users), need a very simple deployment baseline, or are building on existing OpenChat tooling — OpenChat 3.5 is still a solid choice. Its C-RLFT training also produces slightly different response characteristics that some users prefer for conversational tasks. But if you're starting fresh and have no licensing constraint, Llama 3.1 8B is the stronger model.
